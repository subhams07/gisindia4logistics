# Support

## Usage and troubleshooting

Before opening an issue:

1. Read the [README](README.md) and [User Manual](docs/USER_MANUAL.md).
2. Confirm the problem occurs on the latest default branch.
3. Record the operating system, Python version, command, and full non-secret error message.
4. Identify the dataset and data vintage when the issue is data-related.

Use the appropriate GitHub issue template:

- **Bug report** for reproducible software defects.
- **Data quality report** for coordinates, geometry, joins, counts, or stale records.
- **Source or license concern** for attribution and redistribution questions.
- **Feature request** for proposed capabilities.

## Security

Do not disclose vulnerabilities publicly. Follow [SECURITY.md](SECURITY.md).

## Boundaries and official decisions

This project is for logistics analysis. Its maps and boundaries are indicative and are not authoritative government boundary certifications. Do not use GitHub issues to request official boundary determinations.
